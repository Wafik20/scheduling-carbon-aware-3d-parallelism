## Current evaluator semantics
- `evaluate_carbon_policy.py` supports explicit legacy CSV or calibration JSON via `--strategy-profile`; default embedded profile is synthetic demonstration data, not hardware measurements.
- Baselines: one static policy per strategy; Greedy; `Fixed Start Time Dynamic Parallelism` = discretized dynamic-programming oracle with future trace access, hourly decisions and exact simulator replay. Optional `--include-job-shift` adds fastest-static job shifting and shift+dynamic oracle (default search window 24h, step 1h). RL is separately opt-in. Fixed-start oracle is an upper-bound planning method, not a deployed online scheduler.
- Dynamic policies require >=2 strategies. A profile with only one valid strategy provides no evidence of switching benefit.
- Feasible means target tokens completed AND exact completion time <= deadline; waiting counts for shifted jobs. Static/Greedy simulations may run to 1.5x deadline for diagnostics, so completed does not imply feasible.
- Primary savings: for each scoped run and `(episode, offset_h)`, select lowest-carbon exact-deadline-feasible static schedule, then compute `(static_g - dynamic_g)/static_g`. Aggregate feasible dynamic rows with a same-episode feasible static baseline. Mean per-episode percentages is primary, not ratio of mean carbon and not best single static policy over the whole run. Missing baselines must remain missing, not zero savings.
- Report feasibility, paired denominator, missing-static count, reshard-zero fraction, and reshard>0 subset. Otherwise selection-only oracle schedules can be mistaken for switching benefits. Historical metric correction explicitly changed regional interpretation.
- Simulator default idle power is 50 W/GPU; startup/fresh build/general fixed switch overhead default zero, while per-profile save/warmup/reshard terms matter. Explicitly document what is measured versus assumed and power scope. No constants were changed during this audit.
